WHAT WAS IMPLEMENTED
================================================================================

Three inventory operations with transaction-safe audit logging:

1. RECEIVE_GOODS
   ├─ Captures: beforeQty, delta, afterQty, batchId, warehouseId, referenceNo
   ├─ Location: GoodsReceiptsService.post() (lines 450-522)
   └─ Validates: beforeQty + delta = afterQty

2. TRANSFER_STOCK
   ├─ Captures: before/after for both from and to warehouses
   ├─ Location: StockTransfersService.post() (lines 235-310)
   └─ Validates: source math (before - qty = after) + dest math (before + qty = after)

3. STOCK_ADJUSTMENT
   ├─ Captures: adjustmentType, reason, beforeQty, delta, afterQty
   ├─ Location: DamagedStockService.post() (lines 152-215)
   └─ Validates: beforeQty + delta = afterQty

KEY ARCHITECTURE:
- All audit logs created INSIDE Prisma transaction
- If inventory update fails, audit log doesn't exist (and vice versa)
- RequestId flows end-to-end: HTTP header → middleware → controller → service → database
- Delta semantics (beforeQty, delta, afterQty) instead of oldValues/newValues snapshots
- Entity history queryable: GET /audit?entity_type=INVENTORY&entity_id=<product-id>

ARCHITECTURE PATTERN (PROVEN IN DAY 3)
================================================================================

This transaction-safe audit pattern will be reused in Days 4-5:

await prisma.$transaction(async (tx) => {
  // 1. Read current state
  const before = await tx.stockSummary.findUnique({...});

  // 2. Validate business rules
  if (before.qty < requested) throw error;

  // 3. Update primary entity
  await this.stock.postMovementOnce(tx, {...});

  // 4. Capture new state
  const after = await tx.stockSummary.findUnique({...});

  // 5. Insert audit with metadata
  await this.audit.log({
    action: AuditAction.RECEIVE_GOODS,
    metadata: {
      beforeQty: before.qty,
      delta: requested,
      afterQty: after.qty,
      ...otherFields
    }
  }, tx);

  // 6. Return committed state
  return result;
});

Benefits:
  - Audit trail is complete (no records lost)
  - Inventory and audit always consistent
  - RequestId enables distributed tracing
  - Can replay all decisions from audit_logs
